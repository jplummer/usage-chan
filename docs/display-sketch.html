Tick treatments at the coincidence case

The hard moment is a tick sitting within a pixel of the block edge — exactly on pace. Drawn here at utilization 61%, elapsed 62%. Each mark carries a one-pixel halo in the background colour, so it holds its shape on the dark track and on any fill colour behind it.

What the geometry encodes

left edge of block = utilization
Remaining budget is anchored right, so spending pushes its left edge rightward. Both markers travel the same way: time flies like an arrow.
tick position = elapsed ÷ window length
Deterministic, not estimated. Never jumps, never revises, needs no burn-rate model — which is how it sidesteps the volatility that makes fuel-gauge projections untrustworthy.
reset time sits at the right edge
It labels the moment the right edge encodes, so the geometry explains itself. It also gets sharper as the window tightens while the budget figure gets vaguer — precision migrating from what you can't control to what is certain.
gap between the markers = the whole read
Tick left of the edge means behind pace: calm, however little remains. Tick right means burning faster than the window carries — the one state worth a colour change.
the 7-day window is a line, not a bar
It moves 1% per 100 minutes, so a bar for it is seen hundreds of times per window and looks identical nearly every time — wallpaper. It promotes to a full bar only when representative-claim says it is the binding limit, which was 23% of requests in a 37,000-request capture.
a message is as big as what it invalidates
Weak signal costs you nothing but latency, so it is a small glyph. A Claude service issue means your numbers are right and your work is still blocked, so it gets its own line. No network means nothing on screen can be trusted, so it covers everything.
the WiFi mark is arcs, never bars
Bars beside the pace bars would read as a second gauge. Hidden entirely above −75 dBm, where signal stops affecting a fetch.
